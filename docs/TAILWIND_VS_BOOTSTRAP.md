# Bootstrap или Tailwind: сравнение и обоснование выбора

## 1. Задача

Нужно было перевести готовый интерфейс магазина «Орбита» на утилитарный CSS,
сохранив Vue.js, адаптивность и все интерактивные состояния, и обеспечить
надёжный запуск проекта одним `.bat`-файлом.

Рассматривались два варианта:

1. **Bootstrap 5** — набор готовых компонентов и сетка.
2. **Tailwind CSS v4** — утилитарные классы и собственная дизайн-система.

## 2. Сравнение

| Критерий | Bootstrap 5 | Tailwind CSS v4 |
| --- | --- | --- |
| Подход | Готовые компоненты: navbar, modal, card, table, form-control | Набор атомарных утилит, из которых собирается собственный компонент |
| Внешний вид | Узнаваемый «бутстраповский» стиль, который приходится переопределять | Полный контроль над дизайном без переопределений |
| Кастомизация | Через Sass-переменные, пересборку темы и `!important` | Через `@theme`: цвета, шрифты, радиусы, тени, отступы |
| JavaScript | Собственный JS для dropdown, modal, collapse; конфликтует с реактивным состоянием Vue | JS не нужен: открытие модалок, меню и dropdown управляются состоянием Vue |
| Адаптивность | Фиксированная сетка из 12 колонок и брейкпоинты `sm/md/lg/xl` | Те же mobile-first брейкпоинты, но в виде префиксов у любой утилиты |
| Интерактивные состояния | Готовые классы компонентов (`btn-primary`, `:hover`) | Явные варианты `hover:`, `focus:`, `active:`, `disabled:`, `group-*`, `peer-*`, `data-*` |
| Размер CSS | Подключается целиком либо требует ручной настройки PurgeCSS | Генерируются только реально использованные классы (JIT) |
| Скорость разработки | Быстрый старт на типовых блоках, медленная доводка под макет | Чуть медленнее старт, зато правки интерфейса делаются прямо в разметке |
| Поддержка в Vue | Классы компонентов смешиваются с логикой, сложно переиспользовать | Утилиты комбинируются через `:class`, хорошо ложатся на `<script setup>` |
| Риск «своей» CSS | Почти всегда появляется файл с переопределениями | Свои стили сводятся к токенам `@theme`, слоям `@layer` и утилитам `@utility` |

### Вывод сравнения

Bootstrap выигрывает, когда нужен типовой интерфейс «из коробки» и нет
дизайн-макета. В этом проекте макет уже был нарисован: космическая палитра,
нестандартные карточки, свечения, стеклянные панели. На Bootstrap пришлось бы
переопределять почти каждый компонент, а его JS дублировал бы логику Vue.
Поэтому выбран **Tailwind CSS v4**.

## 3. Способ подключения Tailwind

Использован **сборочный вариант через официальный плагин `@tailwindcss/vite`**.

```js
// frontend/vite.config.js
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [vue(), tailwindcss()],
})
```

```css
/* frontend/src/style.css — точка входа Tailwind */
@import 'tailwindcss';
@import './styles/components.css';

@theme {
  --color-space-950: #030712;
  --color-brand: #5ce1e6;
  --font-display: 'Untitled1', 'Inter', sans-serif;
  --radius-panel: 1.5rem;
  --shadow-glow: 0 12px 30px -10px rgb(92 225 230 / 0.15);
  --container-page: 90rem;
  --spacing-section: 5rem;
}
```

### Соответствие привычному `tailwind.config.js`

В Tailwind v4 конфигурация перенесена в CSS, поэтому отдельного
`tailwind.config.js` нет. Это не отказ от настройки, а новый штатный способ:

| Tailwind v3 | Tailwind v4 в проекте |
| --- | --- |
| `theme.extend.colors` | токены `--color-*` в `@theme` |
| `theme.extend.radius/shadow/...` | `--radius-*`, `--shadow-*` в `@theme` |
| `theme.screens` | `--breakpoint-*` в `@theme` |
| `content: [...]` | автоматическое сканирование файлов плагином Vite |
| `darkMode: 'class'` | `@custom-variant dark (&:where(.dark, .dark *))` |
| `plugins: [require(...)]` | `@utility` и `@layer components` в CSS |

### Почему не CDN

| Критерий | CDN (`cdn.tailwindcss.com`) | `@tailwindcss/vite` (выбран) |
| --- | --- | --- |
| Работа без интернета | Нет | Да, пакет установлен локально |
| Режим | Play CDN, генерирует стили в браузере | Полноценная сборка Vite |
| Производительность | Дополнительный скрипт и генерация на клиенте | CSS собран заранее, минифицирован |
| Продакшен | Не рекомендуется авторами Tailwind | Штатный способ для Vite |
| Токены `@theme` | Ограниченно | Полная поддержка |
| HMR | Нет | Мгновенное обновление стилей |

Сборка проекта даёт около **100 КБ CSS (16 КБ в gzip)** — в файл попадают
только использованные классы. Основной объём приходится на витрину, каталог,
мастер подбора и панель управления с десятками состояний и вариантов.

## 4. Как выполнены требования по Tailwind

- **Только утилиты.** Все компоненты и страницы свёрстаны классами Tailwind.
  Bootstrap, jQuery и Popper удалены из `package.json`.
- **Минимум собственного CSS.** `frontend/src/style.css` содержит
  `@import 'tailwindcss'`, дизайн-токены и три обоснованных исключения:
  - `@font-face` для фирменного шрифта (не выражается утилитой);
  - базовые стили `body`, скроллбара и анимаций в `@layer base`;
  - декоративные утилиты вроде `stars-bg` в `@utility`.
  `frontend/src/styles/components.css` — компонентный слой `@layer components`:
  повторяющиеся наборы классов (`.panel`, `.btn-*`, `.field-input`,
  `.chat-*`, `.data-table`, `.stat-card`) вынесены в `@apply`, чтобы разметка
  оставалась короткой. Собственных «сырых» CSS-правил, кроме `@apply` и
  кастомных утилит, нет.
- **Дизайн-система.** Цвета, шрифты, радиусы, тени, контейнер и вертикальные
  отступы заданы в `@theme` и используются как `bg-space-950`, `text-brand`,
  `rounded-panel`, `shadow-glow`, `max-w-page`, `py-section`.
- **Адаптивность.** Mobile-first брейкпоинты `sm:`, `md:`, `lg:`, `xl:`:
  сетка каталога 1 → 2 → 3 → 4 колонки, бургер-меню до `md`, таблицы с
  горизонтальной прокруткой на телефоне.
- **Состояния.** `hover:`, `focus:`, `active:`, `disabled:`, `group-hover:`,
  `peer-*` и `data-*` (например, `data-open` у бургер-меню и `aria-expanded`
  у выпадающего меню).
- **Логика — в Vue, внешний вид — в Tailwind.** Бургер-меню, dropdown и модалка
  переключаются реактивным состоянием, а их вид описан классами Tailwind.

### Возможности Tailwind v4 в проекте

- `@theme` — токены без `tailwind.config.js`;
- `@custom-variant dark` / `light` — классовая тема вместо `darkMode: 'class'`;
- container queries (`@container`, `@sm:`, `@2xl:`) — карточки каталога
  перестраиваются по ширине контейнера, а не окна;
- `has-[:checked]:*` — подсветка выбранного radio/checkbox без JS;
- `data-[state=*]` — оформление шагов формы по атрибуту;
- `@utility` — собственные утилиты (`scrollbar-thin`, `scrollbar-none`);
- arbitrary values (`[&::-webkit-scrollbar]:w-2`) — кастомные скроллбары.

## 5. Сквозная светлая и тёмная темы

Тема переключается классом `dark` / `light` на `<html>`. Компонент
`useTheme` хранит выбор в `localStorage` (`orbita-theme`), а inline-скрипт в
`index.html` применяет его до первой отрисовки. В `style.css` для
`html.light` переопределяются токены `--color-space-*` и `--color-white`,
поэтому все страницы магазина и панель управления получают светлые поверхности
без дублирования классов. Переключатель — кнопка солнца/луны в навбаре с
`role="switch"` и `aria-checked`.

## 6. Где применены возможности Tailwind

Все интерфейсы проекта — обычные страницы работающего магазина:

| Интерфейс | Маршрут | Что демонстрирует |
| --- | --- | --- |
| Главная | `/` | hero с градиентными свечениями, сетка карточек, состояния наведения |
| Каталог | `/catalog` | фильтры и чипы, сортировка, пагинация, мобильная панель фильтров |
| Подбор | `/selection` | многошаговый мастер с прогрессом и сводкой |
| Услуги | `/services` | pricing-таблица тарифов, FAQ |
| О магазине | `/about` | карточки команды, показатели |
| Поддержка | `/support` | мессенджер, контактные карточки, FAQ |
| Вход и регистрация | `/login`, `/register` | формы с валидацией и состояниями ошибок |
| Панель управления | `/admin` | sidebar-дашборд, показатели, таблица заказов |
| Заказы | `/admin/orders` | Kanban-доска со сменой статуса |
| Товары | `/admin/products` | таблица с модальными формами |
| Импорт | `/admin/import` | загрузка файла и предпросмотр разобранных строк |
| Файлы | `/admin/files` | список загрузок и удаление |

Общие компоненты — `AppNavbar` (навигация, меню пользователя, мобильное меню,
переключатель темы), `AppFooter`, `PriceTag`/`CurrencySign` и `AdminShell`.
